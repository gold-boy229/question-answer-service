## Запус сервиса
### docker compose up
1. Склонировать проект на вашу машину:
`git clone https://github.com/gold-boy229/question-answer-service .`
2. Создать .env файл с переменными, указанными в empty.env одним из способов:
    1.  На Windows: `copy empty.env .env`
    2.  На Linux: `cp empty.env .env`
    3. Свой вариант
3. Опицонально. Задайте нужные вам значения переменным в .env файле
4. Выполните команду `docker compose up`

## Описание проекта
Описание будет представлено в алфавитном порядке названия папок в корне проекта и за что каждая из этих папок отвечает
1) .vscode - содержит описание задач, которые можно запускать в VSC. Что-то тип алиасов для неудобных команд
2) cmd - содержит точку входа в приложение
3) db - содержит папку с миграциями БД (созданые через migrate/migrate), а также рукописный cli-migrator, который запускает эти миграции. Подробнее можно почитать [ниже](https://github.com/gold-boy229/question-answer-service?tab=readme-ov-file#%D1%80%D0%B0%D0%B1%D0%BE%D1%82%D0%B0-%D1%81-%D0%BC%D0%B8%D0%B3%D1%80%D0%B0%D1%86%D0%B8%D1%8F%D0%BC%D0%B8-%D1%87%D0%B5%D1%80%D0%B5%D0%B7-command-line-interface "ниже")
4) docs - содержит pdf с тестовым заданием и папку api с API спецификацией (написанной ручками)
5) internal - рассмотрим ниже
6) Остальное - файлы, лежащие в корне проекта, названия которых говорит за себя.

### Структура папки /internal
Описание будет представлено в алфавитном порядке названия папок внутри /internal:
1) app - содержит объявление всего приложения, задание эндпоинтов и список интерфейсов для обработчиков
2) config - загружает конфиг БД из .env файла или из переменных окружения docker'a
3) consts - содержит константы проекта
4) dto - содержит DTO структуры, в которые:
  - Парсятся входные данные
  - Преобразовываются выходные данные

5) entity - содержит структуры, используемые в бизнес логике
6) enum - перечисление кодов ошибок API 
7) handlers - пакет с http-обработчиками. В каждом файле лежит метод, который обрабатывает некую пару (http-метод + путь эндпоинта)
8) mocks - хранит моки интерфейсов для тестов
9) model - содержит структуры через которые происходит взаимодействие с данными в БД 
10) repository - слоя репозитория. Отвечает за логику взаимодействия с БД. Каждый файл содержит содержит метод (+ вспомогательные функции), который вызывается внутри какого-то http-обработчика. 
11) routes - хранит константы для http-запросов, например, названия path-параметров

### Работа с миграциями 
#### Работа с миграциями через Visual Studio Code 
Добавил задачи в Visual Studio Code (далее VSC) (tasks), с помощью которых можно:
1. Создавать новую миграцию (.up и .down), с нужным вам названием - "Create Migration";
2. Применить/отменить миграцию/миграции - "Run migrations". Эта команда ожидает два ввода: 
	1. Тип миграции: up|down (обязательное поле);
	2. Количество миграций, которые нужно выполнить (опциональное поле).

Запуск задачи в VSC:
1. Ctrl + Shift + P;
2. Tasks: Run Task;
3. Выбрать из списка нужный task или ввести его назавние.

#### Работа с миграциями через Command Line Interface
1. Создать новую миграцию - `migrate create -ext sql -dir ./db/migrations <new_migration_name>`;
2. Запустить миграцию:
	1. Через рукописный cli-migrator.go - `go run ./db/cli-migrator.go up|down [N]`. Принцип работы: 
		1. Читает переменные окружения из .env файла, чтобы подключиться к БД;
		2. Читает аргументы командной строки;
		3. Выполняет миграции.
    2. Через командную строку - `migrate -source file://./db/migrations -database "postgres://<DB_USER>:<DB_PASSWORD>@<DB_HOST>:<DB_PORT>/<DB_NAME>?sslmode=disable" up|down [N]`. Принцип работы такой же как в предыдущем пункте. Отличие только в том, что тут вам самим нужно подставлять значения переменных в шаблон URL'a БД.
